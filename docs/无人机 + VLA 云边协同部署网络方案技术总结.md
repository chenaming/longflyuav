# 三、校园网络现象分析

## 3.1 为什么交换机 13 号口显示“未连接”？

根据会话中对交换机照片的描述，该交换机带有端口隔离拨码功能，当前可能处于类似以下模式：

> 1—14 号端口彼此隔离，但都可以与 15、16 号上行端口通信。

如果交换机确实处于这种 VLAN/端口隔离模式，那么：

- 1—14 号端口之间不能直接互相通信；
- 普通接入端口只能与指定的上行端口通信；
- 如果交换机的上行线没有接在 15 或 16 号端口；
- 或者 13 号端口本身未接入有效上行链路；

那么 AX3 接在 13 号口时可能无法访问上级网络。

### 需要注意的技术修正

VLAN 隔离通常是二层转发层面的隔离，**不一定会导致网口物理链路指示灯熄灭**。因此：

- 如果 AX3 显示“网线未连接”，首先应检查网线、端口协商、交换机端口状态；
- 如果只是“无法上网”或“无法获取地址”，才更可能是 VLAN、端口隔离、认证或上联配置问题；
- 不能仅凭“VLAN 隔离”就断定一定是物理链路断开。

### 更可靠的排查顺序

1. 查看交换机端口指示灯；
2. 更换一根确认正常的网线；
3. 将 AX3 依次插入其他端口；
4. 确认交换机上联线插在哪个端口；
5. 检查交换机拨码开关是否处于端口隔离模式；
6. 用笔记本直接接交换机端口，观察是否能够获取地址；
7. 向网络管理员确认该端口是否绑定 VLAN、MAC 或认证策略。

## 3.2 为什么墙上网口可以连接，但“自动获取 IP”显示失败？

你将网线从交换机 13 号口拔出，改接到柱子下方墙上的预留网口后，AX3 页面显示物理连接成功，但自动获取 IP 后提示互联网连接失败。

这个现象可以拆成三个不同阶段：

### 第一阶段：物理链路建立

墙上网口与 AX3 之间已经建立以太网链路，说明：

- 网线基本正常；
- 墙上端口可能连接到了楼宇交换机；
- AX3 WAN/LAN 端口能够检测到链路。

### 第二阶段：获取内网地址

后来 AX3/AP 下游设备获得了类似：

```text
10.49.11.114
```

这说明网络中很可能存在 DHCP 服务，或者设备使用了某种自动地址分配机制。

因此，“DHCP 获取失败”和“无法访问互联网”不能简单等同。更准确地说，可能是：

- AX3 的互联网探测失败；
- 网关需要网页认证；
- 网关对新接入设备的 MAC 地址未授权；
- 该端口只能访问部分校园内网；
- DNS 或默认路由尚未通过认证开放；
- AX3 的路由模式与校园网认证机制不兼容。

### 第三阶段：校园网认证

你登录校园网账号和密码后，互联网恢复正常。这基本可以确认：

> 学校网络采用了 Portal 网页认证、账号认证、MAC 认证或类似的接入控制机制。

因此，问题不是简单的“没有网线”或“没有 DHCP”，而是：

```text
物理接入成功
    ↓
获得校园内网地址
    ↓
访问外网前需要身份认证
    ↓
认证成功后开放互联网访问权限
```

## 3.3 为什么 AP 模式下可以 Ping 工作站，但不能访问 Bilibili？

将 AX3 设置为 Bridge/AP 模式后，AX3 不再承担传统路由器的主要功能，而更像一个无线接入点或二层交换设备：

```text
手机/笔记本/Orin
        ↓ Wi-Fi
      AX3 AP
        ↓ 网线
   校园局域网
        ↓ 跨网段路由
二楼工作站 10.62.25.215
```

此时设备可能直接从学校网络获得 `10.49.x.x` 地址，而不是由 AX3 分配 `192.168.3.x` 地址。

### 能够 Ping 通工作站说明什么？

能够 Ping 通：

```text
10.49.11.114 → 10.62.25.215
```

至少说明：

- 设备已经接入某个校园内网；
- 两个网段之间存在可用的三层路由；
- ICMP 流量没有被完全阻断；
- 工作站的网络接口和 IP 地址基本可达。

### 不能访问 Bilibili 说明什么？

不能访问 Bilibili，可能是以下原因之一：

- 校园网外网访问需要 Portal 认证；
- 当前设备尚未完成网页认证；
- 该 VLAN 仅允许访问校内资源；
- DNS 解析被限制；
- 默认网关尚未授权；
- 学校对新接入设备进行了 MAC 地址绑定；
- 网络出口需要代理或认证客户端。

你登录校园网账号后即可上网，进一步说明主要原因是**校园网认证未完成**，而不是 AX3 本身损坏。

## 5.1 方案一：校园网络 + AX3 AP

## 5.2 方案二：二楼到工厂直接拉长网线

### 方案 A：4090 直接连接 Orin

```text
4090 网口
    │
    │ 50 米 Cat6 网线
    │
Orin NX 网口
```

两端使用静态 IP，例如：

```text
4090：192.168.50.10
Orin：192.168.50.20
子网掩码：255.255.255.0
网关：可以留空
```

这种方式最简单，也最适合测试纯点对点通信。

### 方案 B：4090 接 AX3 LAN，Orin 通过 AX3 Wi-Fi

```text
4090 网口
    │
    │ 50 米网线
    │

    │ Wi-Fi
    │
Orin NX
```

此时可以让 AX3 作为私有局域网网关，工作站和 Orin 使用同一个私有网段，例如：

```text
4090：192.168.50.10

```

### 关键注意事项

如果目的是让工作站主动访问无人机，通常不建议把工作站接在 AX3 的 WAN 侧、Orin 放在 AX3 的 LAN 侧，因为这样会引入 NAT 和防火墙。

更合适的做法是：

- 工作站接 AX3 LAN；
- 或工作站直接接 Orin；
- 或者在 AX3 上配置静态路由和端口转发；
- 不要在没有明确配置的情况下依赖 DMZ 作为长期方案。

### 优点

- 延迟低；
- 丢包率通常最低；
- 网络完全独立；
- 不受校园网 Portal 和外网策略影响；
- 适合高可靠地面测试。

### 缺点

- 布线困难；
- 无人机起飞后仍然受网线限制；
- 需要保护网线，防止绊倒、拉扯和损坏。

### 适用阶段

- 桌面调试；
- 无桨调试；
- 系统集成；
- 固定位置测试；
- 网络性能基准测试。

## 5.3 方案三：成对无线以太网网桥

### 典型拓扑

```text
二楼 4090 工作站

        │ 网线
        │
```

### 适用阶段

- 真机飞行；
- 固定地面站到移动无人机的通信；
- 需要 SSH、图像和控制数据统一传输的系统；
- 校园网质量不稳定时的专用链路。

# 六、无线网桥板到底有什么作用？

你提出过一个很关键的问题：

> Orin NX 已经有 Wi-Fi，也可以用网口直连笔记本，为什么还要在 Orin NX 网口上接一个网桥板，笔记本电脑上也接一个网桥板？

答案是：

> **网桥板不是为了替代桌面网线，而是为了在无人机起飞后，用无线方式延伸 Orin NX 的以太网连接。**

## 6.1 桌面直连时不需要网桥板

静态调试时：

```text
笔记本
  │
  │ 普通网线
  │
Orin NX
```

这种方式具有：

- 配置简单；
- 延迟最低；
- 速率高；
- SSH 稳定；
- 适合 VS Code Remote-SSH；
- 适合代码同步和系统配置。

此时不需要网桥板。

## 6.2 无人机飞行时不能使用物理网线

无人机起飞后，工作站与 Orin NX 之间不可能继续拖着普通网线。因此需要：

```text
笔记本/4090
    │
地面端网桥
    ║ 无线链路
机载端网桥
    │
Orin NX
```

网桥板的作用是：

- 把 Orin NX 的有线以太网接口连接到无线链路；
- 把 TCP/IP 数据包通过无线链路传到地面；
- 在地面端恢复成普通以太网；
- 让笔记本或 4090 可以继续使用 SSH、HTTP、WebSocket、ROS 等协议。

从系统角度看，网桥两端设备像是通过一根很长的网线连接起来。

# 七、无线网桥与数字图数传的关系

会话中多次讨论“网桥板”和“图数传”的区别。准确理解如下。

## 7.1 传统串口数传

传统数传通常提供：

- UART/串口；
- MAVLink；
- 低速遥测；
- 飞控状态和控制指令传输。

它本身通常没有标准 IP 网络能力，因此不能直接运行：

- SSH；
- HTTP；
- WebSocket；
- ROS TCPROS；
- ROS2 DDS；
- RTSP。

如果强行在串口上运行 IP 协议，需要使用 PPP、SLIP 或类似机制，配置复杂且带宽有限。

## 7.2 传统视频图传

传统图传通常负责：

- HDMI、SDI、AV视频或专用视频流；
- 将视频传到地面接收端；
- 与电脑网络通信相互独立。

它不一定能够让 Orin NX 与工作站形成完整的 IP 局域网。

## 7.3 以太网图数传或无线网桥

以太网图数传通常具有：

- RJ45 或板载以太网接口；
- IP 数据传输能力；
- TCP/UDP 透明传输；
- 可运行 SSH、HTTP、WebSocket、ROS、RTSP；
- 地面端和机载端成对工作；
- 可能支持二层透明桥接或三层路由。

因此，对于 VLA 项目而言，真正重要的不是设备名称中是否叫“图数传”，而是确认它是否具备：

- 以太网接口；
- IP 透明传输；
- 足够的上行和下行带宽；
- 稳定的低延迟；
- 断线重连或链路恢复能力；
- 足够的抗干扰能力；
- 合适的机载重量和供电方式。

# 八、LQ 图数传在项目中的定位

会话中讨论了阿木实验室 LQ-3、LQ-5、LQ-Mesh 等设备。

如果具体型号确实支持以太网透明桥接，那么它可以被视为：

> **面向无人机的专用无线以太网桥或以太网图数传。**

## 8.1 LQ 类设备可以承载的数据

理论上可以承载：

- SSH；
- VS Code Remote-SSH；
- HTTP；
- WebSocket；
- TCP；
- UDP；
- RTSP；
- 压缩图像；
- 位姿数据；
- ROS1 TCPROS；
- ROS2 DDS，但 ROS2 的发现机制仍需额外配置。

## 8.2 不能直接假定的参数

以下参数必须以具体型号说明书和实测结果为准：

- 实际有效吞吐量；
- 上行和下行带宽是否对称；
- 延迟是否稳定；
- 是否支持二层透明桥；
- 是否支持广播和组播；
- 是否支持 MAC 帧透传；
- 是否支持多节点接入；
- 是否有 NAT 或 DHCP；
- 是否支持 Mesh；
- 频段是否合法且适合工厂环境；
- 机载端重量和功耗；
- 断线重连时间。

因此，不能简单认为“LQ 一定能达到 40 Mbps、10 ms 或几公里”，这些都应该通过产品规格和现场测试验证。

# 九、VLA 系统的推荐软件架构

会话后期逐渐形成了一个比较合理的架构：

```text
┌──────────────────────────────┐
│ 二楼 RTX 4090 工作站          │
│                              │
│ OpenVLA/VLA 推理服务          │
│ FastAPI/WebSocket/gRPC Server │
└──────────────┬───────────────┘
               │ IP 网络
               │
        无线网桥 / 校园网络 / AX3
               │
┌──────────────▼───────────────┐
│ 无人机 Jetson Orin NX         │
│                              │
│ Edge Agent                   │
│ 相机采集、压缩、上传           │
│ 位姿和里程计读取              │
│ 接收 VLA Action               │
│ 坐标系转换、限幅、平滑         │
│ 发送给 ROS/PX4/MAVROS         │
└──────────────┬───────────────┘
               │
               │ 本机通信
               │
        飞控 PX4/ArduPilot
```

## 9.1 4090 工作站负责什么？

4090 负责：

- 加载 OpenVLA 或其他 VLA 模型；
- 接收 Orin 上传的图像；
- 接收任务指令；
- 执行 GPU 推理；
- 返回动作、目标位姿或航点；
- 保存推理日志；
- 记录网络和模型性能。

如果采用 Web API 架构，4090 工作站不一定需要安装 ROS1。

## 9.2 Orin NX 负责什么？

Orin NX 负责：

- 读取机载相机；
- 获取飞控状态；
- 获取里程计或定位信息；
- 对图像进行压缩；
- 通过 WebSocket/HTTP 上传数据；
- 接收 VLA 预测结果；
- 将 VLA 输出转换为局部控制目标；
- 执行动作限幅、平滑和安全检查；
- 将安全后的控制量发送给飞控；
- 在网络失联时触发悬停、降落或人工接管。

## 9.3 为什么推荐 WebSocket/HTTP，而不是让 4090 直接运行 ROS1？

主要原因是环境解耦：

| 方案 | 4090 工作站 | Orin NX | 主要特点 |
|---|---|---|---|
| 纯 ROS1 | 安装 ROS1 + VLA 环境 | ROS1 | ROS 集成方便，但环境兼容性和跨网络配置较复杂 |
| ROS1 + WebSocket | 运行 VLA 服务 | ROS1 + WebSocket 客户端 | 推荐方案，兼顾 ROS 控制和模型环境隔离 |
| 纯 Web API | 运行 VLA Server | Edge Agent + 飞控接口 | 灵活、跨平台，需自行设计通信协议 |
| ROS2 分布式 | ROS2 + DDS | ROS2 | 适合统一 ROS2 系统，但需处理 DDS 网络发现和组播问题 |

推荐采用：

> **4090 运行纯 Python/PyTorch/OpenVLA 服务，Orin NX 运行 Edge Agent 和本地 ROS/飞控节点。**

# 十、HTTP、WebSocket、ROS 和传统串口的关系

## 10.1 HTTP/REST

适合：

- 单次请求-响应；
- 低频图像上传；
- 模型推理接口；
- 配置和状态查询；
- 调试阶段。

示例：

```text
Orin NX ──POST 图像──> 4090
Orin NX <──JSON Action── 4090
```

缺点是每次请求都可能涉及请求头、连接管理和请求调度，不适合极高频的控制回路。

## 10.2 WebSocket

适合：

- 持续双向通信；
- 连续图像上传；
- 持续返回推理结果；
- 心跳检测；
- 状态推送；
- 低频到中频控制闭环。

示例：

```text
Orin NX ──建立 WebSocket 长连接──> 4090
Orin NX ──持续发送图像/位姿──────> 4090
Orin NX <──持续返回 Action──────── 4090
```

需要注意：

> WebSocket 本身不自动保证断线重连，心跳、重连、超时和消息序号需要在客户端和服务端代码中实现。

## 10.3 ROS1

ROS1 的通信机制主要包括：

- ROS Master 的 XML-RPC 注册；
- 节点之间的 TCPROS；
- 可选的 UDPROS；
- 节点根据 Master 获得彼此地址后建立连接。

ROS1 不完全依赖广播发现，但跨网段运行时必须确保：

- `ROS_MASTER_URI` 正确；
- `ROS_IP` 或 `ROS_HOSTNAME` 正确；
- 两端节点公布的 IP 可达；
- Master 的 `11311` 端口可达；
- 节点动态 TCPROS 端口没有被防火墙阻断；
- DNS/主机名解析不会返回错误地址。

例如：

```bash
# 4090 工作站
export ROS_MASTER_URI=http://10.62.25.215:11311
export ROS_IP=10.62.25.215
```

```bash
# Orin NX
export ROS_MASTER_URI=http://10.62.25.215:11311
export ROS_IP=10.49.11.X
```

不过，如果使用“4090 VLA Server + Orin Edge Agent”方案，4090 可以不安装 ROS1，ROS 只保留在 Orin 端。

## 10.4 ROS2

ROS2 使用 DDS，网络发现经常依赖组播。跨网段或经过校园网络时，可能受到：

- 组播被过滤；
- VLAN 隔离；
- 防火墙；
- DDS 网卡选择错误；
- 多网卡路由冲突；

等因素影响。因此 ROS2 跨网段部署通常需要配置：

- 固定网卡；
- DDS Discovery Server；
- 单播发现；
- 指定 CycloneDDS 或 Fast DDS 配置；
- ROS Domain ID；
- 防火墙规则。

## 10.5 传统串口数传

串口适合：

- MAVLink；
- 低带宽遥测；
- 飞控命令；
- 简单二进制协议。

不建议直接在传统串口数传上运行 HTTP/JSON。更适合：

- 使用 MAVLink；
- 自定义二进制协议；
- Protobuf；
- 固定长度结构体；
- CRC 校验和序列号。

# 十一、关于 ROS1 与 Web API 的问题总结

## 问题一：工作站上是否也需要安装 ROS1？

### Gemini 的回答

如果使用纯 ROS1 架构，4090 需要安装 ROS1；如果使用 HTTP/WebSocket，4090 只运行 Python、PyTorch 和 OpenVLA，不需要安装 ROS1。

### 技术结论

这个判断基本正确。推荐：

```text
4090：Python + PyTorch + OpenVLA + FastAPI/WebSocket
Orin：ROS/ROS1/ROS2 + Edge Agent + MAVROS/PX4 接口
```

这样可以避免：

- ROS1 与现代 Python 环境冲突；
- ROS1 与 PyTorch/CUDA 依赖冲突；
- 工作站安装复杂机器人软件栈；
- 让推理服务与飞控软件过度耦合。

---

## 问题二：是否需要编写 HTML/HTTP 服务器？

### Gemini 的回答

如果使用 ROS 原生通信，不需要编写 HTML/HTTP 服务器；如果使用 Web API 架构，则需要在工作站运行 FastAPI/WebSocket 服务。

### 技术结论

准确地说：

- 不需要编写网页前端 HTML；
- 但如果采用 Web API 架构，需要编写一个轻量级网络服务；
- 服务可以使用 FastAPI、WebSocket、gRPC 或普通 TCP；
- HTTP/WebSocket 服务不是“网页”，而是给 Orin 调用的机器接口。

推荐的 API 数据流：

```json
{
  "timestamp": 1720000000.123,
  "frame_id": "camera_front",
  "image_format": "jpeg",
  "pose": {
    "x": 0.0,
    "y": 0.0,
    "z": 1.2,
    "yaw": 0.15
  },
  "instruction": "飞向前方红色目标"
}
```

返回动作可以设计为：

```json
{
  "request_id": "abc123",
  "action_type": "relative_pose",
  "action": {
    "dx": 0.20,
    "dy": 0.00,
    "dz": 0.05,
    "dyaw": 0.10
  },
  "valid_until": 1720000000.323
}
```

## 问题三：工作站和无人机是否需要知道双方 IP 和端口？

### Gemini 的回答

WebSocket 架构中，Orin 作为客户端，只需要知道工作站的 IP 和端口；工作站监听 `0.0.0.0:8000`，不需要预先知道 Orin 的 IP。

### 技术结论

这个结论基本正确：

```text
Orin NX：客户端
4090：服务端
```

Orin 主动连接：

```text
ws://10.62.25.215:8000/ws
```

工作站服务端监听：

```text
0.0.0.0:8000
```

工作站不需要提前知道 Orin 的固定 IP，因为 TCP/WebSocket 连接由 Orin 主动建立。

但是仍然需要注意：

- 工作站防火墙必须允许 `8000/tcp`；
- 校园网必须允许 Orin 访问该端口；
- 4090 的 IP 最好固定或通过 DHCP 保留；
- Orin 端需要实现自动重连；
- 服务端要验证客户端身份；
- 消息必须带时间戳、序列号和有效期；
- 控制指令不能无限期执行。

# 十二、VLA 数据流和控制闭环

推荐的数据链路如下：

```text
相机
  ↓
Orin NX 图像采集
  ↓
JPEG/H.264 压缩
  ↓
WebSocket/HTTP 上传
  ↓
4090 VLA 推理
  ↓
输出目标位姿/航点/动作块
  ↓
返回 Orin NX
  ↓
坐标系转换与安全限幅
  ↓
本地控制器/PID/FSM
  ↓
MAVROS/PX4
  ↓
无人机飞控
```

## 关键工程原则

### 1. VLA 不应该直接承担飞控稳定控制

VLA 推理速度通常低于飞控控制频率。更合理的分工是：

- 飞控本身负责姿态稳定；
- Orin 上的本地控制器负责速度、位置和航点跟踪；
- VLA 以较低频率输出高层动作或目标位姿；
- 本地控制器将目标转换为高频控制量。

例如：

```text
VLA 推理：5–20 Hz
本地控制器：20–100 Hz
飞控内部姿态环：更高频率
```

具体频率取决于模型、控制器和飞控接口。

### 2. VLA 输出应优先设计为高层动作

例如：

- 相对位姿增量；
- 局部目标点；
- 速度目标；
- 短时动作块；
- 航点序列。

不要直接让远程 VLA 通过网络控制电机或姿态底层环路。

### 3. 必须在 Orin 本地实现安全机制

至少包括：

- 网络超时；
- 动作有效期；
- 最大速度限制；
- 最大位移限制；
- 最大偏航角速度限制；
- 指令序列号；
- 旧指令丢弃；
- 模型服务断开后的悬停；
- 人工遥控优先；
- Kill Switch；
- 无桨测试模式；
- 电量和定位状态检查。

# 十三、关于 VLA 微调和数据采集的讨论

## 13.1 是否必须微调？

会话中的结论是：

> 不建议一开始就直接微调，应该先进行 Zero-shot 推理测试，再根据失败原因决定是否采集数据和微调。

需要区分两类问题：

### 模型视觉理解失败

例如：

- 看不清目标；
- 识别不了工厂中的物体；
- 不理解新的相机视角；
- 室内光照和预训练数据差异过大。

这类问题可能需要：

- 场景数据；
- 视觉域适配；
- LoRA；
- 视觉编码器或 Action Head 微调。

### 控制和动力学执行失败

例如：

- 输出动作过冲；
- 无人机响应滞后；
- 位置跟踪误差较大；
- 动作块与实际机型不匹配。

这类问题不一定首先需要微调模型，更应该优先处理：

- 坐标系转换；
- 控制器参数；
- 速度和加速度限制；
- 动作平滑；
- 飞控接口；
- 本地闭环控制。

## 13.2 UAV-Flow 类数据

建议记录：

- FPV 图像或视频；
- 时间戳；
- 6-DoF 位姿；
- 线速度和角速度；
- 飞控状态；
- 遥控器输入；
- 实际控制输出；
- 语言任务描述；
- 轨迹起止标记。

数据可以组织为：

```text
trajectory_i/
├── images/
├── poses.csv
├── actions.csv
├── timestamps.csv
└── instruction.txt
```

## 13.3 IndoorUAV 类数据

可以使用：

- 关键帧图像；
- 当前位姿；
- 下一关键帧位姿；
- 相对平移；
- 相对偏航角；
- 高层导航指令。

常见 4-DoF 动作形式：

```text
Δx, Δy, Δz, Δyaw
```

相对位姿计算需要明确坐标系。假设位置为 $p_k$，旋转矩阵为 $R_k$，则可以使用：

$$
\Delta p_{\text{body}} = R_k^T(p_{k+1}-p_k)
$$

偏航角差需要进行角度归一化，例如限制到 $(-\pi,\pi]$：

$$
\Delta \psi = \operatorname{wrapToPi}(\psi_{k+1}-\psi_k)
$$

## 13.4 数据采集建议

建议顺序：

1. 先用 ROS bag 或 rosbag2 完整记录原始数据；
2. 后处理对齐图像与位姿时间戳；
3. 自动提取关键帧；
4. 计算相对动作；
5. 添加语言指令；
6. 先用少量数据验证格式；
7. 再扩大数据规模；
8. 最后进行 LoRA 或 Action Head 微调。

# 十五、对 Gemini 会话中部分结论的技术校正

## 15.1 “VLAN 隔离会导致端口物理未连接”

需要谨慎表述。

更准确的是：

- VLAN/端口隔离主要影响二层转发；
- 物理链路状态由网卡协商决定；
- “未连接”还可能由网线、端口、速率协商或交换机端口禁用导致；
- 应通过端口指示灯和另一台设备进行交叉验证。

## 15.2 “ROS1 默认依赖广播/组播发现”

不够准确。

- ROS1 主要依赖 ROS Master 注册和节点之间的点对点连接；
- ROS1 跨网段可以工作，但必须保证节点公布的 IP、Master 端口和动态节点端口可达；
- ROS2 DDS 的组播发现问题更典型。

## 15.3 “WebSocket 自带自动重连”

不准确。

- WebSocket 提供长连接和双向通信；
- 自动重连需要客户端自行实现；
- 心跳、超时、指数退避、重连次数和状态恢复都需要设计。

## 15.4 “校园网一定带宽充足、延迟稳定”

不能直接假定。

校园网可能有：

- 共享出口；
- VLAN 隔离；
- 认证策略；
- ACL；
- 高峰期拥塞；
- 无线和有线混合链路；
- 设备级限速。

必须通过 `iperf3`、持续 Ping 和真实视频流实测。

## 15.5 “AX3 的 5 GHz Wi-Fi 等同于专业图数传”

不能完全等同。

AX3 是消费级 Wi-Fi AP；专业图数传/无线网桥可能在以下方面不同：

- 天线；
- 射频功率；
- 调制策略；
- 抗干扰能力；
- 链路自适应；
- 断线恢复；
- 机载安装；
- 供电和重量；
- 点对点专用信道。

AX3 可以用于开发和初步测试，但不应自动视为专业飞行链路。

## 15.6 “使用 LQ-Mesh 就一定更适合穿墙和工厂环境”

不能直接下结论。

是否适合取决于：

- 具体频段；
- 天线类型；
- 发射功率；
- 楼板和金属遮挡；
- 实际带宽；
- 设备是否支持 Mesh；
- 现场干扰；
- 国家和地区无线电法规。

需要根据说明书和现场测量决定。

## 15.7 “公网流量一定不会被内网通信消耗”

如果工作站和 Orin 之间的数据包确实在校园内网内部路由，通常不会经过互联网出口。但仍然需要注意：

- 学校可能按校园网络总流量统计；
- 网络认证系统可能记录流量；
- 部分跨 VLAN 流量可能经过统一网关；
- 不能把“不会经过公网”直接等同于“学校一定不计费”。

因此建议查看学校网络使用规则。

# 十九、最重要的最终结论

1. **你当前已经解决的是“基础网络可达性”问题。**  
   AX3 通过墙上网口接入校园网络，在 AP 模式下让 Orin 或其他设备获得 `10.49.x.x` 地址，并成功访问 `10.62.25.215`。

2. **校园网需要账号认证才能访问互联网。**  
   这与内网设备之间能否互相 Ping 通是两个不同问题。

3. **桌面直连网线和无线网桥不是互相替代的关系。**  
   - 网线直连适合静态开发；
   - 无线网桥适合无人机起飞后的远程通信。

4. **网桥板的本质是把 Orin 的以太网接口无线延伸到地面。**  
   它不是 VLA 必需的计算设备，而是为移动无人机提供网络通道。

5. **LQ 一类设备只有在具备以太网透明桥接能力时，才真正适合 SSH、HTTP、WebSocket 和 ROS。**  
   传统串口数传不能直接等同于无线以太网网桥。

6. **推荐使用“4090 VLA Server + Orin Edge Agent”的云边架构。**  
   4090 负责模型推理，Orin 负责传感器、局部控制和飞控接口。

7. **VLA 不应该直接承担无人机的底层稳定控制。**  
   远程 VLA 输出高层目标或动作，真正的高频控制和失联保护应在 Orin/飞控本地完成。

8. **当前最重要的下一步不是立即购买网桥，而是先完成真实网络性能测试和 Mock 闭环。**

9. **如果校园网或 AX3 在移动飞行中表现不稳定，再升级为成对的专用无线以太网网桥或独立专网。**

10. **在任何真机飞行前，都必须完成 Kill Switch、人工接管、无桨测试、网络断开保护和动作限幅。**
