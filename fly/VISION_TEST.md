# 椅子位置与模型动作对照

日期：2026-10-13。保持控制目标发布关闭，全部操作为只读采集和 HTTP 推理回放。

## 方法

从真实桥接请求中按图像时间戳保存相机 JPEG 和 COORD_TRACE，复用原桥接的 RGB → 224×224 → JPEG quality=85 处理。
重建图片 SHA256 与采集记录一致。相机画面中椅子左右位置由图像人工核对，不使用用户口述的移动方向代替图片位置。

- 左侧图片来自请求 13618、13621、13625。
- 右侧图片来自请求 14250、14253、14257。
- 两组指令均固定为 `fly to the chair`。
- 两组 proprio 均固定为 `[0.05268628046740683, -0.025557892137450897, -0.22839999999999996, 0.3383751820507681]`，位置厘米、yaw 度。
- 每张图片重复推理两次，共 6 张图片、12 次请求。重复调用不是独立场景样本。

## 结果

| 图片中椅子位置 | 横向动作 Y 中位数（cm） | Y 范围（cm） |
| --- | ---: | ---: |
| 左侧 | +11.2530 | +11.2530 至 +23.7243 |
| 右侧 | -0.4264 | -0.4264 至 +1.1572 |

同一张图片、相同指令及相同 proprio 的两次响应完全一致。换图后响应不同。
结果支持：本次测试中图像内容会影响模型动作，横向分量随椅子位置变化有明显差异。

限制：右侧三张图片中仍有一张的 Y 为正，因此不能视为可靠的左右方向判定。
场景中可能还有其他家具和物体；没有对象 ID、深度真值、目标到达结果或训练场景覆盖证据。
`server_action_ori_cm_rad` 是下一步动作增量，不是视觉检测得到的椅子绝对坐标。
此测试没有验证椅子三维定位、控制器跟踪、飞控解锁、电机输出或实际飞行。

此前用户报告的“右移”图片实际将椅子移到了画面左侧；按图片方向重新摆放后，才获得本次左右两组。
