# 实时单帧推理闭环飞行入口

文件位于 NX `/home/nvidia/agile/fly`。该入口默认只读；只有显式 `--execute` 才会请求正常解锁、起飞和降落。旧的 `start_fly.sh` 仍只显示预览，旧电机台架入口保持原有用途。

## 当前整轮入口（2026-10-15 更新）

`start_closed_loop.sh` 现在调用 `flight_cycle.py`：在地面未解锁时先关闭上一轮所管理的 NX 程序，再启动 ROS、Odin、MAVROS、控制器内的位置转发、桥接、监控和本地推理转发。主机模型服务保持运行。启动位置转发和新鲜推理检查通过后，才调用底层 `closed_loop_flight.py`；默认和 `--check-only` 均不切模式、不解锁。

无需预先执行 `vla_stack.py start`。一条只读整轮命令：

```bash
cd /home/nvidia/agile
bash ./fly/start_closed_loop.sh --check-only --allow-paired-estimate
```

任务结束后先等待飞控真实上锁、落地、Standby，再关闭 NX 节点。若飞行中切到遥控模式，外部目标立即停止，Odin/MAVROS/位置转发继续运行；整轮启动器最多等待 300 秒让飞手落地并上锁，不自行上锁、切回 OFFBOARD 或关闭定位。超时/失联则保留节点并报错；后续确认落地上锁后可执行 `bash ./fly/start_closed_loop.sh --stop-only` 关闭。已有整轮任务运行时，拒绝并发启动/关闭另一轮。

Odin 高频真实位姿经原 `OdometryBridge` 以约 50 Hz 传入 `/uav1/mavros/vision_pose/pose`，保留源时间戳并停止重复/过期数据；OFFBOARD 位置和 yaw setpoint 另以 30 Hz 发送，两者用途不同。遥控器接管仍以 PX4 实际退出 OFFBOARD 为准，接管后不会自动重新进入；单动油门不由脚本触发接管，飞控的原生保护、解锁/急停开关保持有效。

地面预检对短暂里程计过期最多等待 2 秒，期间持续确认飞控未解锁、落地、Standby；获得新的有效位姿才继续。没有放宽 0.5 秒新鲜度上限或允许不同坐标系；持续异常、坐标系改变仍拒绝。错误输出区分 frame、接收年龄和时间戳年龄。飞行中的故障逻辑保持不变。

当前验证：39 项相关参数/ROS适配器/整轮启停软件测试通过；实际 `start_closed_loop.sh --check-only --allow-paired-estimate` 完整启停通过，全程未解锁、未切模式。定位输出约 49.65 Hz，149/149 个不同源时间戳、转发复制误差 0；该次静止飞控与 Odin 位置差约 1.52 mm。结束后 11311/8088/15017 已释放。这不是实际起飞、椅子到达或空中接管验证；完整外参标定和电机工作时的定位漂移仍未因此得到验证。

## 实现的流程

1. 由整轮入口启动本轮 NX 服务，保留主机推理服务。检查地面、未解锁、定位/遥控新鲜、单份控制器、推理新鲜和 PX4 失联策略。
2. 发布本次自然语言并重置观测原点；等待本次指令、当前图像的新鲜有效结果。这个地面结果只用于启动条件，不作为空中目标。
3. 通过 `/uav1/uav_control_fsm/external_setpoint_control` 交接设定值发布权：原 FSM 保留定位转发，停止发布 setpoint。新节点独占发布 `/uav1/mavros/setpoint_raw/local`。
4. 先以 30 Hz 发送地面保持设定值至少 2 秒，再请求 OFFBOARD。必须从飞控状态确认切换成功；重新检查有新鲜图像结果，才请求正常解锁。确认 armed=True 后开始起飞。
5. 起飞目标为起飞点的 `z + 1.0 m`，保持起飞时的 X/Y/yaw。位置指令按 0.2 m/s 推进，并限制与当前位置的领先距离；这是指令限制，不是实测最大飞行速度保证。
6. 高度/位置误差在 8 cm 内，实际速度和转速低，并稳定 2 秒后，丢弃起飞前和悬停前的结果，只接受悬停完成后拍摄的新图像结果。
7. 接收每个新模型目标后替换当前目标，持续平滑发送位置和 yaw。目标没有 FIFO 队列，不累计多个旧增量。
8. 满足下面的到达启发式时请求 `AUTO.LAND`。确认飞控进入降落模式后停止外部 setpoint，由 PX4 降落。确认在地面持续 2 秒后可请求一次普通上锁；只有真实状态显示在地面且 armed=False 才记为完成。没有强制解锁或强制上锁。

## 最新图像策略

`latest_observation.py` 只保存一张最新图像，新图像覆盖旧图像。短小的里程计历史只用于匹配该最新图像的时间戳，不保存待推理图像队列。最新图像暂时配不上位姿时等待，不退回较旧图像。

桥接默认推理启动频率上限 5 Hz，同时仅允许一个 HTTP 请求。推理过程中继续覆盖图像，完成后在下个调度时刻取最新图像。实际推理频率受服务器耗时限制，不能保证固定 5 Hz。图像进入请求时最多 0.30 秒旧；结果的原始观测年龄仍必须在 2 秒以内。已经发出的那一帧会完成计算，但超时、过期、旧任务或旧原点的结果不会用于控制。

30 Hz 的控制发送与网络推理解耦。推理变慢不会使控制按推理频率断续发送。策略线程卡住超过 0.30 秒则停止延续旧设定值，让飞控已配置的 OFFBOARD 失联策略接管。

## 自动降落判据和限制

这是用户选择的“连续小动作 + 实际稳定”启发式，**不是视觉确认已经到椅子旁**。

- 至少 8 个不同图像、不同请求的有效结果；图像时间和接收时间跨度都至少 2 秒，结果间隔不超过 1 秒。
- 模型原始位移的三维模长不超过 3 cm，原始 yaw 增量不超过 3°；目标相对拍照位姿及当前位姿也满足这个条件。
- 实际速度不超过 0.08 m/s、转速不超过 3°/s，持续稳定至少 2 秒。
- 悬停后导航至少持续 5 秒。重复一个结果、旧帧、无返回、限幅后的假零动作均不计入。

模型如果在错误的位置连续输出小动作，仍会误判到达并降落；报告始终保留 `semantic_goal_verified=false`。不会因为模型返回一个停止动作就证明识别到了椅子。

默认飞行范围：距起飞点水平半径 3 m，导航高度相对起飞点 0.5–1.5 m，导航最长 60 秒；每次目标相对当前/拍照位姿均要求 XY≤0.35 m、Z≤0.05 m、yaw≤8°。没有避障或落点平整度检测。超过模型动作限制的结果拒绝，不放大原有保护阈值。

推理过期先固定位置悬停，连续 5 秒无有效结果则请求异常降落；该结果记为中止，不记为到达。定位、时钟、任务或发布权异常也会中止。`AUTO.LAND` 未确认时保持设定值并报告需要现场接管；不空中强制停机。遥控器切出 OFFBOARD 后不会自动重新进入。Ctrl+C/SIGTERM 请求降落，不等于立即切断电机。

## 使用

### 遥控器接管（2026-10-15 更新）

正式飞行入口不再以油门位置、CH9 电平或 CH6 原始值的变化判断接管，也不增加“油门必须低位”这个脚本启动条件；普通解锁仍由 PX4 本身决定，预检拒绝时不会强制解锁。遥控信号、定位、时钟和失联保护保留。

只以飞控实际 `/uav1/mavros/state.mode` 判断已经离开 OFFBOARD。一旦确认切到 POSCTL、MANUAL、ALTCTL 等其他模式，状态回调锁存交接，发送线程停止发布外部目标。后续自动模式请求、解锁/上锁请求均停止；程序不抢回 OFFBOARD，不因空中接管而强制停机。飞控自身触发的其他模式也按此处理。程序自己请求的 AUTO.LAND 则继续正常的落地确认流程。

在空中先将油门置中再用模式开关选择位置模式，符合用户的接管意图；MANUAL 中位油门并不等于自动悬停。CH9 解锁/上锁、CH10 急停仍按 PX4 映射工作，代码没有屏蔽它们。接管后任务不会自动续跑，原控制器保持 setpoint 静默、继续转发定位；要恢复任务，应先人工落地并上锁，再释放原发布权并明确启动新任务。

当前只读配置：`RC_MAP_FLTMODE=6`、`RC_MAP_ARM_SW=9`、`RC_MAP_KILL_SW=10`、`COM_RC_OVERRIDE=1`，其中 OFFBOARD 摇杆接管位未启用。程序未修改飞控参数；如果后续读到该位已启用，预检会提示与模式开关接管策略不符。

这一版本已通过 22 项策略测试、10 项 ROS 适配器测试（服务端点均为假对象）、13 项台架策略/看门狗判据测试、3 项台架适配器测试。覆盖油门变化不触发接管、中位油门通过脚本预检、模式切换立即禁止外部目标、接管后无自动模式/上锁服务、故障和接管同时发生、程序自己的 AUTO.LAND。没有据此宣称空中接管实飞已通过。

NX 服务由整轮入口统一启停，主机推理服务保持运行。不要同时执行模型传递测试或电机台架测试，也不要在飞行中从旧输入终端更改任务或重置原点。直接运行底层 `closed_loop_flight.py` 的调试行为不包含整轮服务管理。
