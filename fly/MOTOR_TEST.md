仅用于全部拆除螺旋桨、可靠固定、操作者在现场观察并具备停止手段的地面台架。
该物理状态已由用户在当前会话明确确认。它不适用于带桨或飞行中的无人机。

当前 `fly to the chair`、run_id=`chair-00866a5ee82c` 的八个真实模型目标，经过受限中间点发送到现有控制器后，全部得到对应 setpoint。

## 本阶段入口

只读检查，不解锁、不切模式、不更换控制器：

```bash
bash /home/nvidia/agile/fly/test_motor_chain.sh --check-only
```

现场已准备好时，亲自执行一次：

```bash
bash /home/nvidia/agile/fly/test_motor_chain.sh --props-removed --fixed
```

执行时保持其他输入终端空闲，不改指令，不移动无人机，观察电机是否转动及是否停转。
脚本会正常请求解锁，在已解锁 OFFBOARD 中测试约 5 秒，然后请求上锁。
现有监督器临时交接控制器，测试后恢复禁止已解锁执行的默认台架控制器；Odin、MAVROS、主机推理和桥接保留。
保留原有安全清理过程，成功情况下会在未解锁 OFFBOARD 中继续保持一段时间，再恢复 MANUAL，因此整条命令可能持续约 30–50 秒，电机测试窗口仍约 5 秒。

## 范围与保护

- 模型原目标与实际发送点分别记录，已解锁目标限幅为 XY≤2cm、Z≤3mm、yaw≤1°，小于控制器既有已解锁上限。
- 解锁前要求：飞控已连接/未解锁/Standby、预检 Ok、遥控器信号有效、油门低、CH9 低、当前任务已通过八个未解锁模型样本、单份控制器、无其他 move_command 发布者、新鲜且通过桥接检查的模型目标。
- 解锁前再次检查任务/轮次、目标年龄、飞控状态和遥控器油门/CH9。
- 不使用强制解锁，不关闭预检，不更改 PX4 安全参数，不绕过遥控器检查，不走正常 FSM 的自动起飞分支。
- 租约每 0.04 秒更新；控制器租约要求接收间隔<0.25秒，且具有10秒硬上限。
- 独立看门狗在租约丢失、任务变化、飞控状态异常、遥控器信号丢失/油门升高/CH9 状态变化或已解锁时间超过8秒时请求上锁。
- 正常上锁未确认时，既有台架清理助手仅在明确拆桨上下文下尝试强制上锁（MAVLink400的param1=0）；此恢复路径不计为正常测试通过。
- 未确认上锁时不会主动杀死看门狗和控制器，也不会将结果报告为通过。

## 为什么在 fly 中建立副本

旧电机模块把任务写死为中文“飞到椅子上”，会在当前英文指令下解锁后立即报告 task changed。
先用原条件复现了该错误，再建立 `fly` 内副本，改为匹配真实的当前指令、run_id 和坐标系；同时在解锁前和已解锁循环中检查任务。
内部 motor stage 需要受保护父进程的会话 token 和 PID，不能靠直接运行子模块跳过外层检查。
既有原脚本、桥接和已编译控制器源文件保持原样。

## 证据位置

- `fly/runtime/motor_precheck.json`：本次只读预条件检查。
- `fly/runtime/motor_chain.log`：本次电机测试日志。
- `fly/runtime/motor_chain_report.json`：本次任务的模型目标、实际发送点、setpoint匹配和上锁结果。
- 原兼容报告仍在 `agile/runtime/vla/`，供现有监测面板读取。

成功需要：对应模型 setpoint 比例达到既有检查标准、正常上锁确认、MANUAL恢复、默认 `bench_allow_armed=false` 恢复。
电机实际转动/停转仍需操作者确认；指令对应椅子三维位置、自主导航和避障未通过本阶段验证。
