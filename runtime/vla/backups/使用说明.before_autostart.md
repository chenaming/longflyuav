## 启动与停止

```bash
cd ~/agile
./start_uav.sh                 # 一个窗口五个标签页，默认间隔 5 秒
./start_uav.sh --delay 8        # 改为间隔 8 秒
./start_uav.sh --sensors-only   # 仅 Odin、MAVROS
./start_uav.sh --check          # 检查路径、launch、串口
./start_uav.sh --status         # 查看本次启动状态
./start_uav.sh --stop           # 反序停止本次节点并关闭对应标签页
```

启动顺序为 Odin → MAVROS → 控制 FSM → EGO → RViz。最后一个标签页打开 Odin、EGO 两套 RViz。
不单独执行 `roscore`：第一条 `roslaunch` 在没有 ROS master 时自动启动它。停止 Odin launch 时会一并停止其创建的 master；复用外部 master 时不会停止外部 master。

`~/start_uav.sh` 是新启动脚本的兼容软链接，原来的命令仍然可以用。没有单独的停止脚本。

## 发送目标点

```bash
cd ~/agile
bash send_goal.sh                    # 默认绝对目标 (2, 0, 1) 米
bash send_goal.sh --dry-run          # 检查默认点，不发送
./send_goal.sh 1 0 1                 # 绝对目标 X=1、Y=0、Z=1 米
./send_goal.sh 0.5 0 0.5 --relative   # 相对当前位置的偏移
./send_goal.sh 1 0 1 --dry-run        # 只检查并打印，不发送
```

坐标是规划器局部地图 `uav1_map` 的米制坐标，Z 向上；相对模式沿局部地图轴偏移，不是机头方向。该地图使用 MAVROS 本地定位坐标，不能把 GPS 坐标直接填进来。

脚本检查飞控连接、定位时间戳、目标高度和规划器订阅者，向 `/uav1/goal_point` 发布一次 `quadrotor_msgs/GoalSet`，然后等待规划器的对应接收日志。接收确认只证明目标到达回调，不保证路径可行或飞机到达。

脚本不请求解锁、Offboard 或起飞。进入控制模式后，规划器产生的指令可被控制 FSM 执行。当前配置的高度边界为 -2 到 3 米，脚本会读取运行中的实际参数进行检查。

## 重新编译

```bash
cd ~/agile/agile_ws
bash build.sh

cd ~/agile/odin_ws
source /opt/ros/noetic/setup.bash
catkin_make -j2 -l2
```

`build.sh` 按自身所在目录定位工作空间，无参数时默认使用 `-j2 -l2`；可通过 `bash build.sh -j4 -l4` 覆盖。它按原有顺序编译控制器、EGO、视频模块和轨迹任务。

## 定位与配置

- 飞控：`/dev/ttyTHS0:921600`。
- Odin 里程计：`/uav1/odin1/odometry`；原始点云：`/uav1/odin1/cloud_raw`。
- 控制器里的 `Fast_Lio` 是兼容配置名，实际 remap 到 Odin；没有启动 Fast-LIO 算法。
- Odin 时间戳采用主机接收时间，尚未标定硬件采集同步及安装外参。
- RViz 独立配置保存在 `~/.local/state/uav-bringup/`，修改显示后可以保存。
- 日志入口：`~/.local/state/uav-bringup/latest/`。
- 迁移前的编译产物与修改前的构建脚本已备份到 `~/.local/state/uav-bringup/rebuild-backup-20260922-154232/`。
